Migration Fleet

Modernizing 120 Python services with an orchestrated fleet of Cursor Cloud Agents — standardize tooling, upgrade the runtime, in dependency order, with human review.

Built on the Cloud Agents REST API · demo runs a sanitized model of a real migration.

The problem — the same medium problem, 120 times

120 Python services. Each set up by a different team at a different time — different build scripts, different dependency setups, all pinned to an old Python.

The ask: standardize them onto one template + toolchain (copier · uv · just) and move them to Python 3.14.

  • Not one hard problem — the same medium problem 120×, each repo subtly different.
  • Some import each other, so order matters.
  • By hand: a person-quarter of error-prone, unauditable toil.

The part a per-repo bot can't do — ordered waves + gates

wave 1
common-utils DONE
→ wave 2
notifications-svc DONE
risk-scoring NEEDS REVIEW
→ wave 3
payments-ledger BLOCKED
  • Shared library migrates first — consumers never migrate against an un-migrated dep.
  • risk-scoring → needs-review — it didn't fake success; it couldn't resolve a pin and flagged it. At 120 repos, that triage is the product.
  • payments-ledger → blocked — imports risk-scoring, so the engine refused to touch it against an unclean base.
  • Import cycles are detected and flagged for a human, not hung on.

The whitespace: agentic reasoning + fleet ordering + native Cursor + fit to one enterprise's stack. Deploying that into a customer's migration is the FDE job.

Trade-offs, limits, roadmap

decisions
  • Python + REST API — meet the customer in their stack (vs richer TS SDK)
  • PRs, never auto-merge — humans own the merge
  • Block consumers on unclean deps — safety over throughput
limits → roadmap
  • Polling → webhook-driven runs
  • Coarse gates → richer policy / SCA integration
  • Template reconciliation is the riskiest step
  • Cost scales with fleet → triage matters more than throughput

Same engine runs the next campaign — "rebuild every service on API v2" — not just this one.
